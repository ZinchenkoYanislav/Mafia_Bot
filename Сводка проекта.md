# Mafia Bot — сводка проекта

> Автосгенерировано анализом кода `C:\Projects\Mafia_Bot` — 2026-08-27.

## Назначение

Telegram-бот для организации игр в «Мафию»: админы создают «афиши» (события) с датой, местом и лимитом мест, игроки записываются через бота, автоматически формируется лист ожидания.

## Стек

- **grammY** (`grammy` + `@grammyjs/conversations`) — фреймворк Telegram-бота, диалоги (conversations) для пошаговых сценариев
- **Prisma + SQLite** — ORM и БД
- **TypeScript**, `tsx` для dev-режима (`tsx watch`), сборка через `tsc`
- **dotenv** — конфиг из `.env` (`BOT_TOKEN`, `ADMIN_IDS`)

Скрипты (`package.json`): `dev`, `build`, `start`, `db:migrate`, `db:studio`, `db:generate`.

## Модель данных (Prisma, SQLite)

- **User** — `id` (BigInt, Telegram ID), `username`, `firstName`
- **Event** — заголовок, дата, место (+адрес/координаты), лимит игроков, цена, ведущий, постер (file_id), описание, `status` (`open` / `closed` / `cancelled` / `finished`), `reminderSent`
- **Registration** — связь User↔Event, `status` (`registered` / `waitlist` / `cancelled`), уникальность по паре (userId, eventId)

Миграции: `init` → `add_location_geo` → `add_reminder_flag` (3 миграции, БД в актуальном состоянии).

## Архитектура (`src/`)

| Файл | Назначение |
|---|---|
| `bot.ts` | Точка входа: регистрирует модули, `/start`, запускает фоновые джобы |
| `config.ts` | Конфиг из env (`botToken`, `adminIds`), `isAdmin()` |
| `db.ts` | Синглтон Prisma-клиента |
| `context.ts` | Типы контекста grammY (+conversations) |
| `keyboards.ts` | Reply-клавиатуры для игрока и админа |
| `notify.ts` | Рассылка сообщения всем записанным на конкретную игру |
| `cleanup.ts` | Крон раз в час: авто-архивация игр через 12ч после старта (`open` → `finished`) |
| `reminders.ts` | Крон раз в 15 мин: напоминания за 2ч до игры основному составу, флаг `reminderSent` |
| `player/games.ts` | Игрок: список игр, «мои игры», запись/отмена с логикой листа ожидания и автопродвижения, рендер карточки игры |
| `admin/pickers.ts` | Диалоговые пикеры: дата/время (год→месяц→день→час→минуты через inline-кнопки), ведущий (из списка админов/вручную/пропустить), локация (venue/геопозиция/текст) |
| `admin/createEvent.ts` | Пошаговый сценарий создания афиши (conversation) |
| `admin/manageEvents.ts` | Админ-панель: список афиш, карточка управления (открыть/закрыть/отменить/удалить/оповестить), рассылка по конкретной игре |

## Что готово ✅

- Регистрация пользователя в БД при `/start` и при первой записи
- Просмотр открытых игр карточками (текст или фото-постер + инлайн-кнопки)
- Запись на игру / отмена записи, автоматический лист ожидания и продвижение из очереди при отмене
- Раздел «Мои игры» для игрока
- Создание афиши админом через пошаговый диалог: заголовок → дата/время → локация → лимит мест → цена → ведущий → постер → описание
- Управление афишами: список всех, смена статуса (открыть/закрыть/отменить), удаление с подтверждением
- Точечная рассылка сообщения участникам конкретной игры (свободный текст)
- Автооповещение участников при отмене игры организатором
- Автоархивация прошедших игр (крон, раз в час)
- Автонапоминания за 2 часа до старта основному составу (крон, раз в 15 мин, без повторной отправки)
- Разграничение прав admin/player по `ADMIN_IDS` из `.env`
- Поддержка геопозиции места (venue из Telegram) со ссылкой на Google Maps

## Чего не хватает / потенциальные пробелы ⚠️

- Нет тестов и CI
- Нет README и инструкций по деплою (Docker/systemd и т.п. не настроены)
- Ошибки доставки сообщений (заблокировал бота и т.д.) молча проглатываются — нет логирования/ретраев
- Список афиш (`ev:list`) не пагинирован — при большом числе игр карточка станет громоздкой
- Нет ролей кроме admin/player (например, со-организатор конкретной игры)
- SQLite — ок для текущего масштаба, но не рассчитан на высокую параллельную нагрузку
- Нет редактирования уже созданной афиши (только смена статуса/удаление — изменить дату/место после создания нельзя)

## Итог

Функционально бот закрывает полный цикл: создание афиши → запись игроков → напоминания → управление/отмена → архивация. Основной пользовательский и админский флоу реализован и выглядит рабочим; из «продакшн-обвязки» отсутствуют тесты, деплой и редактирование афиш постфактум.
